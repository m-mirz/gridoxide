# UCTE-DEF fixtures

Six network files taken verbatim from [powsybl-open-rao][rao]'s own test
resources, plus a pypowsybl reference solution for each.

[rao]: https://github.com/powsybl/powsybl-open-rao

## Why these six

| File | What it is there to catch |
|---|---|
| `TestCase12Nodes.uct` | The canonical case: 12 nodes, 15 lines, one 380/380 phase shifter at its neutral tap. Zero magnetizing admittance, so agreement with pypowsybl is limited only by solver tolerance. |
| `TestCase12NodesDifferentPstTap.uct` | The same network with the phase shifter at **tap 16 of 16**. This is what validates the symmetrical tap formula — at tap 0 every candidate formula agrees. |
| `TestCase_severalVoltageLevels_Xnodes.uct` | 400/225 transformers and X-nodes. A mis-referred impedance is a ~3% error here and invisible on a 400/400 unit. |
| `TestCase16Nodes_with_different_imax.uct` | Distinct current ratings per line, a closed busbar coupler, out-of-service branches, and a second phase shifter at tap 5. |
| `3nodes_pst.uct` | A phase shifter at tap **−8**. Sign errors survive every positive-tap test. Its transformer has zero reactance, so it is used for tap assertions only and not for a flow comparison. |
| `TestCase12Nodes_wrong.uct` | Deliberately malformed — node records before any `##N`/`##Z` header. Both gridoxide and pypowsybl reject it. |

## The `.pypowsybl.json` files

Generated by `scripts/bench/ucte_reference.py`; re-run it after adding a
fixture and commit the result. The Rust test reads the JSON, so `cargo test`
needs neither Python nor pypowsybl.

Each document holds the slack bus that was used, the load-flow status, per-node
voltage magnitude (per-unit) and angle (degrees), and per-element terminal
flows in MW/MVar. `null` marks a de-energised element.
