## The cross-format three

`TestCase12Nodes`, `TestCase12NodesDifferentPstTap` and
`TestCase_severalVoltageLevels_Xnodes` are pypowsybl exports of the UCTE
fixtures of the same name. They exist so that gridoxide can read one network
through two parsers that share no code — fixed-column text and XML — and be
required to agree. The UCTE side is itself checked against pypowsybl, so
agreement here pins both importers at once.

Regenerate them with:

```python
import pypowsybl as pp
pp.network.load("../ucte/TestCase12Nodes.uct").save("TestCase12Nodes.xiidm", format="XIIDM")
```

## The native five

Written as IIDM in the first place, covering what UCTE cannot express.

| File | Version | What it is there to catch |
|---|---|---|
| `TestCase2Nodes.xiidm` | 1_0 | The oldest schema version, and the `currentLimits1` spelling. |
| `nordic32.xiidm` | 1_8 | 52 buses, 80 branches — the largest, and bus-breaker throughout. |
| `voltage_monitoring.xiidm` | 1_8 | **Node-breaker**: 17 switches, busbar sections, and a bus view that has to be computed from the switch graph. |
| `network_with_dangling_lines.xiidm` | 1_13 | Tie lines paired by key through `danglingLine`, and the `operationalLimitsGroup` spelling. |
| `network_one_voltage_level.xiidm` | 1_15 | 50 switches, and **temporary limits** with acceptable durations. |

Together with the exports (1_17) the set spans five schema versions.

## The `.pypowsybl.json` files

Generated by `scripts/bench/iidm_reference.py`; re-run it after adding a fixture
and commit the result, since the Rust suite reads the JSON and needs neither
Python nor pypowsybl.

No slack bus is forced. IIDM carries none of its own, so gridoxide picks one and
pypowsybl picks one; these fixtures are near-lossless, so the choice barely moves
the flows, and the comparison reports the distance rather than assuming it.
